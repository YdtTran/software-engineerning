# Use-case refactor impact

The proposed eight entries are an overview of actor goals. Keep the existing UC IDs as scenario anchors so the individual submissions, diagrams, and prototype walkthroughs remain traceable. The current baseline has 14 core cases, six supplemental lifecycle scenarios, and 27 visible goals including seven secondary actions. The eight-entry proposal changes the overview's level of detail.

## Refactor order

1. **Establish a green baseline.** The use-case checker currently expects exactly two Draw.io files, but the repository also tracks detailed and general drawings. The sequence checker finds zero of its seven expected files in its current lookup. The process checker looks for activity verification under the diagram folder, while tracked verification lives under `.agent/verification`. Align checks to the intended deliverables before using them to judge the refactor.
2. **Add a lifecycle-to-UC crosswalk.** Keep the existing detailed scenario IDs and all 11 scenario fields. Use lifecycle groupings to update the overview, submission index, and architecture traceability without renaming scenario files or browser routes.
3. **Merge the simulation overview first.** Update the old UC13-to-UC14 include relationship and dependent labels together. Preserve both screens and scenario references. Verify one successful evaluation yields metrics and recommendations, and only an explicit, validated handoff can request live action.
4. **Group trip, then parking.** Keep separate scenario triggers and verify the cross-workflow capacity rules before changing behavior. Cover cancellation versus pickup claim, uncertain unlock or return, and competition for the last usable parking space across return, parking and transfer.
5. **Group user charging and preserve operator scheduling.** Resolve queue versus rejection, port failure, and the power budget before adding any shared behavior. Verify that cancellation releases only the pending request's holds and that confirmed stop frees session resources. Keep the incident and transfer handoffs explicit.
6. **Regenerate affected outputs and recheck traceability.** Check actor roles, links, Draw.io/export parity, scenario completeness and browser routes. The browser verifier currently imports Playwright from an absolute Windows path, so portability needs attention before it can serve as a Linux baseline.

## Review scope

Static review of tracked project artifacts, prototype entry points and verification wiring. The checks in step 1 were run against the existing tree and failed as described. Browser journeys, exported layout and hardware behavior were outside this review. The proposed backend is documented design; the current runnable app is the browser prototype.
